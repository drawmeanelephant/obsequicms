# P02 work report: Astryx application shell

Status: complete. Branch `m0-prototype`. Depends on P01.

## What was built

- `apps/web/src/shell/workspaces.ts` — the eight workspace destinations,
  their labels, one-line limit statements, and the `workspace`/`scenario`
  query-parameter interface (parse + href building) from
  docs/api.md#prototype-composition. Pages→inventory and
  Structure→outline mapping lives in `WorkspaceOutlet`.
- `apps/web/src/shell/useWorkspaceRoute.ts` — query-parameter router:
  real anchors keep keyboard and middle-click semantics; activation is
  intercepted into `history.pushState`, back/forward follow `popstate`,
  and the scenario parameter is preserved across navigation.
- `apps/web/src/shell/AppNavigation.tsx` — persistent `SideNav` (Astryx)
  with three labeled sections (Content, Site, Workspace) covering all
  eight destinations; `aria-current="page"` through `isSelected`.
- `apps/web/src/shell/PlaceholderWorkspace.tsx` — honest not-connected
  state for Editor, Media, Analytics, Publish, and Settings, each stating
  what the area cannot do; no sample content, no fake actions.
- `apps/web/src/shell/WorkspaceErrorBoundary.tsx` — render-error boundary
  so a typed request error neither blanks the screen nor falls back to
  demo data.
- `apps/web/src/shell/WorkspaceOutlet.tsx` — keyed remount per workspace;
  mounts the real features for Pages/Structure/Readiness.
- `apps/web/src/App.tsx` — `AppShell` (Astryx) with top navigation brand,
  side navigation, banner slot, and the workspace outlet. `App` receives
  the injected `client` and an optional `banner`; App itself stays
  demo-agnostic.
- Demo entry composition (P02-owned): `main.tsx` reads the scenario,
  creates `createDemoClient(scenario)` explicitly, wraps in the Astryx
  `Theme`, and passes the banner; `demo-entry/DemoScenarioBanner.tsx` is
  the persistent, non-dismissable "Demo data" notice with a labeled
  scenario select (full navigation so the entry recreates the client);
  `demo-entry/scenario.ts` validates the parameter against the six names.
- `index.css` imports the Astryx reset/base CSS and adds small product
  CSS (demo banner strip, workspace padding). The neutral theme module
  (`astryx-themes.ts`) was generated by `npx astryx theme add neutral`.

## Shell arrangement comparison (packet requirement)

A temporary `?layout-compare` route rendered all three candidates with
identical destinations and body; screenshots were taken at 1280×800 and
390×844:

- Fixed side navigation: all eight destinations stay visible, labeled, and
  grouped; content keeps full width.
- Compact side navigation (icon rail): loses destination labels; expand
  action is a separate step.
- Top navigation only: eight items overflows Astryx's own guidance (≤5
  TopNav items) and crowds at 1280px.

At 390px all three collapse to the same AppShell mobile drawer, so the
desktop evidence decides. **Chosen: fixed side navigation.** The decision
is recorded in docs/decisions.md; the temporary route and the two
discarded layouts were removed.
