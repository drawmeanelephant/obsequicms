## Outcome

**Read-only M1 now works with real Boris data.** A separate connected browser
entry reads one explicitly server-selected project through a native Node
backend. It compiles/checks isolated copies with the approved Linux kit and
returns real page metadata, compiler-directed relationships, located content
diagnostics, graph-check findings, and exact snapshot source bytes.

This is not a demo-client substitution or a production CMS release. There is
no authentication, save endpoint, authoring UI, preview transport, publishing,
provider connection, or public listener. The original labeled demo remains a
separate entry, with all 45 existing browser checks passing.

Startup instructions: [connected mode](../connected.md).
Compiler acquisition and exact pins: [Boris kits](../boris-binary.md).

## Implemented boundary

- Exactly one project root and compiler executable are operator-configured
  absolute paths: `OBSEQUIOUS_PROJECT_ROOT` and `BORIS_BIN`. The browser cannot
  choose/enumerate roots, executables, workspaces, or flags.
- Only health, site, pages, and source GET endpoints exist. Mutations, sessions,
  jobs, and readiness endpoints remain absent. Unknown request fields and
  path/process controls are rejected with the documented typed error shape.
- The native listener refuses non-loopback binds before opening a socket.
  Host/Origin restrictions supplement this private boundary; they are not
  authentication or permission to deploy publicly.
- Each page-index request verifies the platform digest and compiler identity,
  copies the selected project, optionally validates its profile, then indexes
  and checks the isolated copy. Replacing the executable after an earlier
  success cannot silently authorize new bytes.
- Page IDs, parentage, roles, statuses, tags, and edge directions are projected
  from Boris artifacts. Source folders never supply parentage. Source-only
  includes stay source endpoints. Public URLs/release IDs remain unknown.
- Compiler paths are content-root-relative. Application paths add exactly one
  configured `content/` prefix, including the valid authored case
  `content/content/nested.md`; no prefix guessing is used.
- A fresh content failure is an unavailable graph with no valid graph revision,
  pages, or edges. Real code/message/path/line/column are retained. Remediation
  is included as `Next step:` text in the existing Problem message, without
  changing the P01 contract.
- Unsupported profile/producer data stays unsupported, not an empty current
  site. I/O, transport, and malformed-response failures remain errors. The
  connected client never imports demo scenarios or changes mode on failure.
- Source reads use a known path and exact retained revision, filesystem
  containment, regular-file checks, no-follow opens, bounded reads, and a fresh
  containment check. UTF-8 is decoded without replacement; LF/CRLF/BOM bytes
  and their SHA-256 remain faithful.
- Four snapshot revisions are retained in process memory; old IDs expire
  explicitly. Serial operations prevent overlapping compiler work. Shutdown
  refuses new work, waits for in-flight bounded work, and removes owned copies.
  There is no durable revision store or job runner.

Initial snapshot bounds: 64 MiB copied inputs, 4096 files, 64 directory levels,
8 MiB per input. Generated root directories and environment files are excluded.
Snapshots are private temporary workspaces, never the selected live tree.

### Two different source-size limits

The application SourceBuffer limit is **8 MiB**. The pinned Boris parser's
normative `docs/contracts/frontmatter.md:288` and `src/parser.zig:328-329`
enforce **1 MiB** for parsed page source. An 8 MiB source therefore must not
be advertised as a current valid graph.

Real tests exercise 1 MiB minus one byte, exactly 1 MiB, 1 MiB plus one byte,
exactly 8 MiB, and 8 MiB plus one byte. They require current graphs at the
compiler boundary, real located `EFRONTMATTER` refusals above it, exact raw
source reads through 8 MiB even for a failed snapshot, and application refusal
at the first excess byte. Neither limit nor the compiler was changed.

### Earlier failures and their disposition

  `ResolvConfParseFailed` condition. Two custom-cache seeding attempts timed
  out; default-cache seeding inside a scratch initialized Zig project succeeded,
  with both original dependency hashes unchanged. System DNS was not modified.
- Two 360s full Boris baseline attempts timed out. The final cache-warm run
  completed in 272.5s and passed. The timeouts were tool execution bounds, not
  a user-defined runtime limit; source tests were not changed.

  `bsdtar` selection corrected the tool dialect without modifying Boris or
  system packages.
- The first NodeNext server typecheck exposed P01's extensionless source
  exports. Existing Vite SSR bundling solved native runtime compatibility
  without changing contract schemas or dependencies.
- New test wiring initially used a Playwright-only query option in Testing
  Library, an empty fixture pattern rejected by lint, and a text query that
  also matched Astryx's hidden live-region mirror. Those tests now use exact
  accessible-name patterns and visible main-content scoping; no assertions were
  weakened and no expected product data was regenerated.
- The initial large-file test wrongly assumed the raw-source cap was Boris's
  parser cap. Its actual diagnostic was investigated against the pinned
  normative contract/source; the final test asserts both independent limits.
- Validation found and corrected an initial namespace projection bug for an
  authored subfolder named `content`; a real compiler regression test covers it.
