# P06: real compiler adapter proof

Date: 2026-11-08. Branch: `m0-second-pass`, following the corrective pass
([P05 follow-up](P05-followup.md), commit `7c82f3e`).

P06 establishes the real Boris integration evidence for the pinned baseline:
a bounded, fixed-argv process adapter, producer artifact adapters, and the
explicit compiler gate — proven against a pinned `boris/0.9.0` binary, not
against synthetic dashboards or the previously observed dirty `0.8.2` build.

## What the adapter is (and is not)

Owned code lives in `apps/server/src/boris/`:

- `identity.ts` — opaque compiler-id acceptance (base id or `+variant`
  suffix, exact comparison, no substring matching), `--version` and
  `--build-info` document parsing, entity-id argv-safety boundary.
- `run.ts` — bounded process execution: fixed argv arrays, no shell, 120 s
  deadline, separate 16 MiB stdout/stderr caps, SIGTERM then SIGKILL
  escalation. Outcomes: success 0, content 1, usage 2, io 3, terminated for
  signal/timeout/overrun/unexpected exit.
- `workspace.ts` — unique temporary job workspaces with scoped cleanup and
  fresh output/report preparation (stale files removed before every run).
- `artifacts.ts` — producer artifact parsers: IR `0.2.0` (manifest, graph,
  completion `boris-completion-index`/`schema_version` 1, build report),
  `html-build-report-0.2.0`, and `boris-documentation-intelligence`
  reports. Conditional IR `0.3.0`/`0.4.0` and unknown versions are typed
  `unsupported_version` failures — never reinterpreted as base IR, never an
  empty successful graph. Missing artifacts are typed failures.
- `operations.ts` — the six fixed allowlisted invocations exactly as
  `docs/boris-integration.md` declares them, run inside the job workspace,
  reading artifacts only after a successful process run.

**Not** in this packet: no compiler execution over HTTP, no application
`PageIndex` mapping (that is M1's source/jobs backend), no RSS enablement,
no source editing, no publication.

## Real compiler evidence (gate: `npm run test:boris`)

Every claim below was exercised against the pinned binary by
`apps/server/test/boris/compiler-gate.test.ts` (11 tests). Hand-authored
fixture: `apps/server/test/boris/fixtures/site/` — trunk `index`, satellites
`about` and `guides/ferns`, a draft `guides/ferns-care`, wiki references, and
a source-only include `content/includes/watering-note.md`.

- **Provenance is enforced.** The gate recomputes the binary's SHA-256 and
  compares it to the record before anything runs; `--version` and
  `--build-info` must agree with it.
- **Valid nested pages index successfully.** `build --input content --out
  .obsequious/ir` publishes all four IR `0.2.0` artifacts with the expected
  id-sorted page list and the three-level chain.
- **Producer edge direction comes from actual artifacts.** Parent edges run
  satellite → parent (`guides/ferns-care` → `guides/ferns` → `index`); the
  include names a `source` endpoint (`includes/watering-note.md`) and that
  file is never promoted to a page node; reference edges run from the
  referencing page to the referenced page.
- **`check`, `impact`, `validate --profile`, and `build --profile` succeed**
  and produce `boris-documentation-intelligence` / `html-build-report-0.2.0`
  reports carrying the pinned compiler id and an opaque `vcsRevision` token.
- **A draft page proves default HTML output is not privacy.** After
  `build --profile`, `dist/guides/ferns-care.html` exists with the draft body
  rendered at its route while the emitted search index excludes it.
- **Source bytes remain unchanged** across index and preview runs (whole-tree
  hash before/after).
- **A content failure after an earlier success never yields a current valid
  graph.** With a broken parent reference, the run exits 1 with an
  `EPARENTMISSING` failure report; `graph.json`/`manifest.json`/
  `completion.json` are removed; the adapter returns no artifacts; removing
  the broken file restores success.
- **An unsupported profile declaration remains visible.** A profile with
  `editions.ir` produces a usage outcome (exit 2) whose stderr names
  `editions.ir`; the adapter surfaces it instead of dropping it.
- **Stale artifacts are never evidence.** A pre-seeded stale report at the
  report path is removed before the run; the adapter reads only freshly
  written bytes.

### RSS asymmetry finding (documented, not enabled)

Against the pinned binary, a single-target profile with `rss` and an enabled
`head` (`enabled: true`, `base_url`) is accepted by **both**
`validate --profile` and `build --profile` and emits `dist/feed.xml`;
without the enabled-head rider both refuse with exit 2 naming the field.
The bounded single-target RSS path exists in `boris/0.9.0`, but the
application adapter still does not enable RSS — per
`docs/boris-integration.md`, enabling it is a separate reviewed decision.

### Gate failure behavior

- Without `BORIS_BIN`: the gate fails with an explicit message
  ("BORIS_BIN is not set…") — it does not skip.
- With the wrong binary (the dirty `boris/0.8.2` local build): the gate
  fails at the digest comparison — it does not skip.

## Stub-based process evidence (standard suite: `npm test`)

`apps/server/test/boris/process.test.ts` and `workspace.test.ts` use the
committed controlled executable stub
(`apps/server/test/boris/stubs/scripted-stub.mjs`, a Node script — no
compiler binary involved):

- Exit-code mapping: 0/1/2/3 → success/content/usage/io; 7 → terminated.
- Deadline termination (bounded wall clock), stdout overrun termination with
  the collected prefix retained, SIGTERM→SIGKILL escalation against a stub
  that ignores SIGTERM.
- Argv arrays pass through verbatim (including a shell-metacharacter arg) —
  no shell interpretation.
- Spawn failure reports an `io` outcome naming the cause.
- Workspace uniqueness, double-cleanup safety, stale-tree and stale-report
  removal, and refusal of output paths escaping the workspace.

`apps/server/test/boris/artifacts.test.ts` runs **without** any binary: it
parses the captured real producer artifacts (committed verbatim under
`fixtures/captured/` with a provenance sidecar naming the capturing binary
digest and revision) and asserts the adapter rejections — conditional IR
`0.3.0`/`0.4.0` and unknown versions, unknown compiler ids
(`boris/0.8.2`), wrong discriminators/schema versions on every artifact
family, unfrozen graphs, index/count mismatches, and the entity-id argv
boundary (flag injection, control characters, bounds).

## Remaining limitations

- The adapter is a producer proof layer: it does not yet feed the
  application's `ObsequiousClient` or run inside HTTP handlers — that is the
  reviewed M1 source/jobs work, which starts from this evidence.
- One fixture corpus (Markdown, one HTML target, no editions/rss/llms).
  Conditional IR `0.3.0`/`0.4.0` are proven **rejected**, not supported.
- RSS is not enabled; the asymmetry finding above is recorded for that
  later decision.
- The binary is machine-local (not committed); a fresh environment must
  re-acquire the kit via `agent-pack.sh` and point `BORIS_BIN` at it.
- "Bit-identical IR across operating systems" is not claimed upstream and
  not tested here; the gate ran on Darwin-arm64 only.
